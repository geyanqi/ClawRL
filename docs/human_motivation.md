我们要做的事情就是使用 Codex 全程接管 RL 的数据准备，监控，训练以及 reward 的产出。

你可以理解为我的构想是这样的。

训练启动方面：
我会给你向集群提交 job的一个脚本。他就是你向集群提交训练任务的框架。大概逻辑就是 import 一个 jobbuilder 或者类似的东西，你在里面可以 mount cfs 或者 nas盘啥的。然后里面就有数据有代码，你也可以拿到image，然后就可以以装载了 Codex 的机器作为一个 router，去分发训练任务，拿到训练日志。
当然，可以 request Codex 的router 同样是可以挂在 cfs的，也就是说大家有一个共同的盘去交换数据。

数据方面：
从业务角度来说，我们一般会以一个裸模作为 baseline 发到线上。这时候呢其实每天都会回流很多数据进来。我们就可以去批量的扫 badcase，并且在以裸模为 model 的 pipeline 上线前会有一套机器评测的指标来引导业务迭代。所以你可以假设我们拥有几个评测的 prompt 和访问数据库的脚本，以及表名等等的，便于我们拿到对话数据。然后去设置一些 Codex 的定时任务去拉 sql，然后再去批量的 Codex 机器评测 扫数据。这样我们就可以源源不断的获取训练数据了！

奖励方面：
我们也可以使用机评时候的评测 prompt 来获得对于rollout 的评分，他就可以天然的转化为reward。去指导我们的训练。也就是说每次 rollout 结束之后的 trajectory 结合获取 badcase 的 prompt 就是我们获取奖励的最简单也是最强的方式，这种 agentic scoring 的效果一定会比部署一个奖励模型更强大。

- 如何加速奖励获取。
由于大量的并行任务会使得 coding agents 通过写正则，写 JavaScript 的方式跳过使用模型。所以在项目的早期必须要做的事情是，把我们的大模型评测 prompt 可以对齐到较小模型上。换句话来说，当我们拿到线上的 100 条数据时（当然一定会有一套策略可以过滤一些明显正确和没必要评测和训练的数据），我们可以起一个 main thread 去下发100 个 subagents 任务。 model = 我们上线时候评测的model，prompt 也是一致的。

于是我们获得了一批可以认为带有 GT 的数据，然后和我们就可以用一个较小的 GPT 模型，比如5.6 luna 而不是 sol 来帮我们评测。让 5.6sol 去优化下发任务时候的 prompt，使得 使用5.6luna的 subagents的评测效果甚至是 gpt 5.3 codex spark 可以接近 5.6sol。但是我们依然会采取一套比如多 session 窗口，每个session 窗口用 5 个 subagents平行评测，这种拆分的方式来保证coding agents 每次都是通过调用 agentic scoring 的方式来获取奖励，而不是通过一些规则和 Python 代码。

我认为这是一个独立并且一定需要在启动训练前完成的工作。

这里其实也分两个阶段，一阶段我们就可以用业务上线时候的评测数据先跑一遍，优化着，等到了发布的第二天有数据回流后再启动小模型 prompt 优化的流程。

- 如何得到数据的奖励
我们可以在 rollout 的过程中把数据存在一个cfs的一个地方，当 Codex 监控到这里有新的数据进来之后就可以下发 subagents任务了


如何做实验和迭代：

首先假设我有 8卡 * 12Node 也就是 96 张 GPU。
那么其实我们做实验阶段的话就希望并行 6 个实验任务，比如我的最终目的是训练一个 qwen3-122b-a10b 的模型。那我就可以先并行 6 个实验任务出来，用qwen3-35b-a3b先训一套最好的，然后再把数据 transfer 到大模型上去。

我认为迭代其实就在
1. 小模型训练过程中应该被监控，比如某步奖励炸了就应该向集群提交杀掉任务的bash，其实说白了就是监视训练 log. 总结一些经验到训练 documents 里面
2. 数据配比. 其实这块我认为可以给 Codex 一些自由度，但也有一些必须的限制。这意味着当他认为缺什么数据，或者想组什么数据配比或者试验方案的时候可以自己提交 job,和拉数据，拉数据当然也是需要先粗筛后main thread 开 subagents啥的方式去过滤，总的来说就是可以通过 training log 去分析和实验，最后得到一套还不错的在小模型上训练的不错的数据出来。
3. 是否需要调整 agentic scoring 的 reward prompt，这块其实我想的不是特别清楚，你可以发挥一下
4. 总的来说我们最终会得到一个在机评口径下（和 reward 评测的口径可以认为是一致的）相比于基模有提升的模型。这时候他的数据和 reward prompt 就可以直接 transfer 到 大模型的训练上，并且监视大模型的 log，决定是否怎么做之类的，后面其实我没有想的很清楚了。
